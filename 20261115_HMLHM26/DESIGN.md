# HMLHM26 再現の設計

## 対象

Hitzig, Massenkoff, Lyubich, Heller, McCrory, "Agentic coding and persistent returns to expertise"
（Anthropic Research、2026-06-16、https://www.anthropic.com/research/claude-code-expertise）。本文の報告書 PDF と
付録 PDF（分類器プロンプトの全文と検証）が公開されている。arXiv にはない。

2025 年 10 月から 2026 年 4 月の対話型 Claude Code セッション 398,198 件（234,751 人）を、Claude Sonnet 4.6 の
分類器（temperature 0.2、選択肢から 1 つ）とテレメトリで分析している。本再現で確かめる主張は次の 3 つ（報告書の原文で確認済み）。

1. 専門性が高いほど、1 プロンプトあたりの Claude の行動と出力が多い。初心者は約 5 行動・約 600 語、
   専門家は約 12 行動・約 3,200 語。統制した回帰で専門性 1 段階あたり行動 +9%、出力 +13%（Figure 3）。
2. 専門性が高いほど成功しやすく、伸びの大半は初心者から中級の間にある。検証された成功は初心者 15%、
   中級以上 28〜33%。少なくとも部分的な成功は 77% と 91〜92%（Figure 5）。
3. トラブル（失敗シグナル 3 以上）に当たったセッションでも同じ傾きがある。検証された成功は初心者 4%、専門家 15%。
   放棄（Failed かつ追加行 0）は初心者 19%、それ以外 5〜7%。

対象外とするもの:

- 判断の帰属（計画の約 70% をユーザー、実行の約 80% を Claude）。分類器のプロンプトが付録に載っていない。
- タスク価値（+27%）。フリーランス求人の較正データと Opus 4.7 の推定プロンプトが必要で、手元で同じものを作れない。
- 時系列の変化（修正 33%→19% など）と職業別の成功率。SWE-chat は公開 GitHub リポジトリのセッションで、
  期間と利用者の構成が報告書と大きく違う。

## データ

- SWE-chat（Hugging Face `SALT-NLP/SWE-chat`、ODC-BY、利用には同意が必要）の v2（2026-10-02 公開、17,968 セッション）。
  報告書も分類器の検証に SWE-chat の 198 セッションを使っている。
- `sessions.parquet` のエージェントが Claude Code で、ユーザーのプロンプトが 1 件以上あるセッションに絞る
  （報告書はヘッドレス実行を除いている）。
- 中身（2026-11-15 に `sessions.parquet` で確認）: Claude Code のセッションは 12,418 件（プロンプト 1 件以上は 12,335 件）。
  利用者 503 人、リポジトリ 599 件、期間は 2026-01-15〜2026-09-04。報告書（2025-10〜2026-04）とは 3 か月重なる。
  利用者の偏りが大きい（最多の 1 人で 531 件、上位 10 人で 19.5%）。標準誤差は利用者でクラスタする。
- `sessions` には SWE-chat 独自のラベル（`user_persona`: Expert Nitpicker、Vague Requester など。`session_success`: 0〜100）がある。
  本再現の専門性・成功のラベルとの対応を副次的に見る。
- データ本体はリポジトリに入れない。`data/` に置き `.gitignore` で除く。コミットするのはセッション ID、ラベル、集計だけ。

## 分類器

- 付録の分類器のうち 5 つを使う: 作業モード（9 区分）、専門性（1〜5 と Unclear）、結果（Succeeded / Partially Succeeded /
  Failed / No clear goal）、成功シグナル（1〜5）、失敗シグナル（1〜5）。
- プロンプトは付録 PDF から `extract_prompts.py` で `prompts/` に取り出す。付録の原文なのでコミットしない。
- 入力は報告書と同じ形にする。人間・アシスタント・システムの各ターンを 5,000 字で中央を切り詰め、全体を 25,000 字で
  切り詰める（先頭と末尾を残し `[TRANSCRIPT TRUNCATED FOR LENGTH]` を入れる）。ツール呼び出しと結果は 1 ターンとして含める。
- 実行は Claude Code 2.1.325 のヘッドレス実行（`claude -p --tools "" --model claude-sonnet-4-6`）。空の作業ディレクトリと
  専用の設定ディレクトリで、1 セッション・1 分類器ごとに 1 回呼ぶ。`claude -p` では temperature を指定できないので、
  報告書の 0.2 とは違う（実験環境の表に書く）。応答したモデルは `modelUsage` で確かめる。
- 選択肢以外を返した呼び出しは同じ条件で 1 回だけやり直し、それでも外れたら欠測にする。

## テレメトリの置き換え

報告書のテレメトリは SWE-chat の記録から次のように作る。

| 報告書 | 本再現 |
|---|---|
| ターン数（人間のプロンプト数） | `conversations` のユーザープロンプト数 |
| 行動数（プロンプトあたり） | 成功したツール呼び出し数 ÷ ユーザープロンプト数。報告書と付録に「行動」の定義はなく、テレメトリとして挙がっているのはモデル呼び出し数と成功したツール呼び出し数なので、モデル呼び出し数でも同じ集計を出す |
| 出力量（プロンプトあたり） | アシスタントの出力の語数 ÷ ユーザープロンプト数（報告書は語数で示し、テレメトリは出力トークン数） |
| 追加行数 | `sessions` のコード帰属と `commits` から、エージェントが追加した行数 |

## 指標と判定

- 報告書の定義をそのまま使う。検証された成功 = 結果が Succeeded かつ成功シグナル 4 以上。トラブル = 失敗シグナル 3 以上。
  放棄 = トラブルかつ Failed かつ追加行 0。No clear goal は成功の分析から除く。
- 専門性の段階ごとに、成功率（Wilson 95% 区間）と、行動数・出力量の幾何平均を出す。
- 回帰は報告書を簡略にする。検証された成功を専門性（線形と段階ダミー）に回帰し、作業モードとモデルの固定効果を入れ、
  標準誤差はリポジトリでクラスタする。タスク価値、月、職業の統制は使えない。
- 次の 2 つがそろえば `OK` とする。(a) 検証された成功が専門性とともに上がり、初心者から中級の上がり幅が中級から専門家より大きい。
  (b) 行動数と出力量が専門性とともに増える。

## モデル別の集計

`sessions.model` で応答モデルを分け、件数が足りるモデル（目安 200 件以上）ごとに主張 1、2 の傾きを出す。
`[1m]` や `us.anthropic.` などの表記揺れはまとめる。

- 件数（Claude Code）: Opus 4.6 850、Opus 4.8 843、Opus 4.7 645、Opus 5 517、Sonnet 5 436、Sonnet 4.6 394、Fable 5 330。
  Haiku 4.5、Opus 4.5、Fable 5.1 は 50 件未満。
- 66%（8,244 件）は `model` が空。2026-02 までは全件が空で、空の割合は月とともに下がる（2026-08 で 10%）。
  空のセッションは `conversations` の記録からモデルを補えるか確かめる。
- 最新の 5.5 系はデータ期間の後に出たので含まれない。比べられるのは 4.6 から 5 系まで。
モデルを選ぶのは利用者なので、利用者の違いが混ざる。統制した比較は拡張研究（`HMLHM26-ext`）で行う。

## 規模と進め方

1. 試走: 50 セッションで 5 分類器を回し、ラベルの分布、外れた出力の割合、1 セッションあたりのトークン数を見る。
2. 費用を見積もってから本数を決める（目安 2,000 セッション、1 万回の呼び出し）。
3. ハーネスは `results/labels.jsonl` に記録済みの (セッション ID, 分類器) を飛ばして再開する。
   `safeguards flagged` で `is_error` になった呼び出しは同じ条件で再試行する。
